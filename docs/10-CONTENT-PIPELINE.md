# 10 — Производство контента и пайплайн ассетов

## 1. Что нужно произвести (объём к релизу 1.0)

| Тип | Кол-во | Оценка трудоёмкости |
|---|---:|---|
| Модели букв (33 заглавных + 33 строчных) | 66 | 1 базовый меш + шрифтовая экструзия → ~3 дня |
| Модели буквят (питомцы) | 33 | ригованные, но однотипные → ~10 дней |
| Косметика (шапки/спины/лица/следы) | ~55 | ~15 дней |
| Иконки предметов | ~103 | рендер из моделей, автоматизируем |
| Картинки к буквам (слово-пример) | 33 | стиль единый, плоские иллюстрации → ~5 дней |
| Элементы полосы препятствий | 20 | 5 базовых готовы серой геометрией → ~8 дней |
| Уровни (11 буквенных + 11 математических) | 22 | ~2 дня на уровень |
| Хаб + Башня | 1 | ~7 дней |
| Озвучка | 63 реплики | 1 студийная сессия + монтаж |
| Музыка | 3 трека | готовы, нужна проверка лицензии |
| SFX | ~40 | библиотека + правка |
| Анимации (эмоции, буквята) | ~25 | ~5 дней |

## 2. Соглашения об именовании

```
Модели букв:      letter_<id>_upper / letter_<id>_lower       → letter_m_upper
Буквята:          pet_<id>                                     → pet_m
Косметика:        <cat>_<name>                                 → hat_stargazer, trail_stardust
Иконки:           icon_<itemId>                                → icon_hat_stargazer
Картинки к буквам: img_letter_<id>                             → img_letter_m
Препятствия:      obs_<kind>                                   → obs_barrier, obs_arch
Аудио:            vo_ru_<категория>_<ключ>_v<N>                → vo_ru_letter_m_v1
Музыка:           mus_theme_<N>                                → mus_theme_1
SFX:              sfx_<action>                                 → sfx_catch_correct
Анимации:         anim_<subject>_<action>                      → anim_pet_idle
```

Только латиница, только нижний регистр, только `_`. Никакой кириллицы в именах файлов —
это ломает пайплайны и Rojo.

## 3. Технические требования к ассетам

**Модели:**
- ≤ 4 000 треугольников на букву, ≤ 8 000 на питомца.
- Один материал на модель, атлас текстур на группу (все 33 буквы = 1 атлас).
- Текстуры 512×512 для мелких объектов, 1024×1024 максимум.
- Pivot в основании модели, ось Y вверх, масштаб в studs (буква для ловли ≈ 4 studs).
- Формат импорта: FBX через 3D Importer, коллизии — `Box` или `Hull`, никогда `Precise`.

**Иконки/UI:**
- PNG с альфой, 256×256, единый отступ 10%.
- Никакого текста внутри иконки (кроме самой буквы).

**Картинки к буквам:**
- 512×512, плоская иллюстрация слова-примера из справочника (А — арбуз, Ж — жук),
  объект в центре, нейтральный фон, узнаваемый силуэт.
- Проверка: «покажи 5-летнему без подписи — назовёт правильно?» Если нет — переделать.
- Картинка **не озвучивается**: слово в игре не читается и не произносится
  ([02-LEARNING.md](02-LEARNING.md) § 4).

## 4. Пайплайн загрузки в Roblox

```
исходник в assets/  →  проверка чек-листа  →  загрузка в Creator Dashboard
      →  модерация  →  запись assetId в Config/AudioRegistry или Config/Assets
      →  коммит  →  сборка проходит тест «все ключи существуют»
```

**Правила:**
1. Всё загружается на **аккаунт группы**, а не личный аккаунт разработчика.
   Иначе при уходе человека ассеты остаются у него.
2. Никаких сырых `rbxassetid://` в коде испытаний и UI — только через `Config/Assets`
   и `Config/AudioRegistry`.
3. Загрузка аудио идёт **пачками заранее** — модерация не мгновенная, закладывайте
   до суток и учитывайте суточные лимиты на загрузку.
4. Каждый ассет фиксируется в таблице `assets/MANIFEST.csv`:
   `key,type,file,assetId,uploadedAt,uploadedBy,status`.
5. Исходники (WAV, FBX, PSD) **не хранятся в git напрямую** — либо Git LFS, либо
   внешнее хранилище с ссылкой в манифесте. В репозитории только манифест и конфиги.

## 5. Чек-лист приёмки озвучки

- [ ] Один файл — одна реплика, имя по конвенции.
- [ ] Тишина 100 мс в начале, 250 мс в конце.
- [ ] Нормализация по LUFS, потолок −3 dBFS, без клиппинга.
- [ ] Буква названа целиком: «Буква М», а не «М» и не «м-м-м».
- [ ] **Согласный разборчив после обработки.** Проверяется на слух и измерением:
      именно здесь споткнулась первая сессия ([05-AUDIO-VO.md](05-AUDIO-VO.md) § 1).
- [ ] П, Б, Т, Д, К, Г различимы между собой на телефонном динамике.
- [ ] Темп на 15–20% медленнее обычного, без сюсюканья.
- [ ] Прослушано ребёнком 5 лет — показал правильную букву?

## 6. Чек-лист приёмки испытания

- [ ] Проходится ребёнком, который не читает (проверено на живом ребёнке).
- [ ] Инструкция звучит автоматически при старте и по кнопке 🔊.
- [ ] Провалить невозможно; выход доступен в любой момент.
- [ ] Награда ≥ 3 ⭐ даже при худшем результате.
- [ ] Все начисления идут через сервер, клиент ничего не решает.
- [ ] Событие `letter_answer` пишется на каждую попытку.
- [ ] 30 FPS на целевом планшете.
- [ ] Ни одного красного «неверно» и резкого звука.

## 7. Локализация (задел на будущее)

Игра моноязычная (русский алфавит — суть продукта), но UI-строки всё равно выносим
в таблицу с ключами. Причина: интерфейс может понадобиться на английском/казахском/
узбекском для семей, где русский — второй язык, при том же обучающем ядре.

- Все видимые строки — через `Localization/Strings.luau`, ключи вида `ui.shop.buy`.
- Озвучка **не локализуется** — она и есть предмет обучения.
- Roblox Localization Tables использовать не обязательно, но структуру держать совместимой.

## 8. Порядок производства (что делать первым)

1. **Аудио: 33 названия букв** — без него ничего нельзя протестировать.
2. Модель буквы (одна) + шейдер/материал — потом размножается на 33.
3. Пять базовых элементов полосы препятствий из серой геометрии уже стоят —
   заменить на модели ([19-OBSTACLES.md](19-OBSTACLES.md) § 6).
4. Хаб: Башня + магазин + гардероб, потом спавн с двумя порталами.
5. 20 предметов косметики для магазина первой играбельной версии.
6. Остальное — по ступеням, по одной целиком (буквы + картинки + уровень).
