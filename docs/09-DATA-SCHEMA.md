# 09 — Схемы данных и справочник букв

Всё содержимое игры описано данными. Ни одна буква, ступень или предмет
не «зашивается» в код испытаний.

## 1. Справочник букв (единственный источник истины)

`id` — ключ во всех системах: профиле, аудио-реестре, аналитике, ассетах.
Латиница выбрана, чтобы не иметь проблем с кириллицей в именах файлов и ключах DataStore.

Порядок — алфавитный, он же порядок изучения ([02-LEARNING.md](02-LEARNING.md) § 2).
Поле «Похожие по написанию» — это `confusableWith`: буквы, которые ребёнок путает
глазами, а не на слух.

## 2. `Config/Letters.luau`

```lua
--!strict
export type LetterKind = "vowel" | "consonant" | "hissing" | "sign"

export type Letter = {
    id: string,
    glyph: string,          -- "М"
    glyphLower: string,     -- "м"
    kind: LetterKind,       -- нужен для цвета и подсказок, не для обучения звукам
    order: number,          -- 1..33, место в алфавите
    stage: number,          -- 1..11
    color: Color3,          -- по виду буквы, см. 08-UX-UI
    vo: { name: string },   -- "letter_m" → «Буква М». Другой озвучки у буквы нет
    example: string,        -- слово-иллюстрация, без озвучки: "МЯЧ"
    confusableWith: {string},
}
```

Модуль отдаёт `ordered()` (алфавит целиком), `byStage(n)`, `at(order)`,
`after(id)` и `before(id)` — последние два нужны «Алфавитной лестнице».

Файл сгенерирован по общей таблице и правится целиком, а не по одной букве:
порядок, ступени и ключи озвучки обязаны оставаться согласованными.

```lua
export type Stage = {
    index: number,                  -- 1..11
    id: string,                     -- "first_three"
    title: string,                  -- «Первые три»
```

всегда начало алфавита без дыр, и вопрос «какая следующая» всегда имеет открытый ответ.

## 4. `Config/Obstacles.luau`

```lua
export type ObstacleKind = "barrier" | "gap" | "arch" | "beam" | "steps"

export type Obstacle = {
    id: string,
    kind: ObstacleKind,
    title: string,
    tier: number,     -- 1 базовый, 2 средний, 3 сложный
    lanes: number,    -- сколько дорожек из трёх занимает
    blocking: boolean, -- нельзя перепрыгнуть, только обойти
}
```

В конфиге лежат **только те элементы, которые сервер умеет строить**. Полный каталог
задуманного живёт в [19-OBSTACLES.md](19-OBSTACLES.md): данные без реализации — это
обещание игре, которое она не может выполнить.

**Инвариант, проверяемый тестом:** ни один элемент не перекрывает все три дорожки.
Элемент, который нельзя ни обойти, ни перепрыгнуть, останавливает ребёнка насовсем.

## 5. `Config/Shop.luau`

```lua
export type ShopItem = {
    id: string,                -- "hat_stargazer"
    category: "hat"|"back"|"face"|"trail"|"pet"|"emote"|"tool"|"bundle",
    title: string,
    price: number?,            -- в ⭐; nil = не продаётся за звёздочки
    robuxProduct: number?,     -- productId, если продаётся за Robux
    tier: number,              -- 0..4
    unlockStage: number,       -- с какой ступени появляется в витрине
    assetModel: string,
    icon: string,
    grantedBy: string?,        -- "letter_mastered:m" — выдаётся автоматически
}
```

**Инварианты:** у предмета должно быть ровно одно из `price` / `robuxProduct` / `grantedBy`.
Один и тот же предмет не может и продаваться, и выдаваться за прогресс.

## 6. `Config/AudioRegistry.luau`

```lua
-- vo_key -> rbxassetid. Единственное место, где живут ID аудио.
return {
    letter_m   = "rbxassetid://0000000001",
    letter_ya  = "rbxassetid://0000000002",
    instr_letter_rain = "rbxassetid://0000000003",
    -- ...
}
```

Ключи букв и музыки не перечисляются руками — они собираются из `Letters` и `Stages`,
чтобы список нельзя было забыть обновить.

Тест при сборке: каждый `vo`-ключ, упомянутый в конфигах, обязан существовать в реестре.
Отдельный тест держит потолок объёма записи: реплик не больше сотни. Он тут не ради
красоты — концепция сменилась именно потому, что 600 реплик записать не вышло
([05-AUDIO-VO.md](05-AUDIO-VO.md) § 1).

## 7. `Config/Challenges.luau` (сложность)

```lua
return {
    letter_rain = {
        targetCount    = { 5, 5, 6, 7, 8 },       -- по уровням сложности 1..5
        distractors    = { 1, 2, 3, 4, 4 },
        fallSpeed      = { 6, 8, 10, 12, 14 },
        spawnInterval  = { 1.2, 1.0, 0.9, 0.75, 0.6 },
        hintAfterSec   = { 6, 6, 8, 10, 12 },
        missCooldown   = { 1.4, 1.2, 1.1, 1.0, 0.9 },
    },
    -- ...
}
```

Уровень сложности хранится **на пару (игрок × испытание)** и двигается по правилам из
[02-LEARNING.md](02-LEARNING.md) § 7. Параметры забегов живут не здесь,
а в `Config/Tunnel`: там геометрия, дорожки и расстояния, и разрывать их надвое бессмысленно.

**Инвариант, проверяемый тестом:** у каждого параметра ровно пять значений,
и ни одно испытание не заявляет, что учит звукам, слогам или чтению слов.

## 8. Профиль игрока

```lua
export type Profile = {
    version: number,
    stars: number, level: number, xp: number,
    letters: { [string]: LetterProgress },
    math: { [string]: TopicProgress },  -- прогресс по ступеням счёта, ключ — id ступени
    stages: { [number]: StageProgress },
    runs: { [string]: SavedRun },   -- незаконченные забеги: где остановился
    levels: { [string]: number },   -- сколько уровней пройдено в каждом мире (§ 8.5)
    tutorial: { [string]: boolean },-- сделанные шаги обучения: catch, shop, run
    base: { [string]: number },     -- участок: уровень каждой категории построек
    inventory: {string},
    equipped: Equipped,
    difficulty: { [string]: number },
    dailyStreak: number,            -- серия дней подряд на день последней игры
    lastLoginDay: number,           -- последний день, засчитанный в серию (§ 8.4)
    playLog: { PlayDay },           -- посуточная история занятий, до 28 дней
    settings: Settings,
    parent: ParentData,
    stats: { totalPlayMin: number, sessionsCount: number, firstJoin: number },
}
```

Клиенту профиль целиком не уходит никогда: срез (`toSnapshot`) не содержит
родительского PIN, лимитов и внутренней статистики обучения.

### 8.1. Участок игрока

```lua
base = { house = 2, roof = 1, yard = 0, fence = 1 }
```

Четыре числа, а не список объектов: улучшение ЗАМЕНЯЕТ предыдущее, поэтому
у категории есть уровень, но нет истории покупок. Дёшево сохранять, нечему ломаться,
и невозможно получить «два дома на одном участке».

Перед постройкой уровни проходят `Base.sanitize`: чужие ключи, дробные и слишком
большие значения срезаются. Профиль приходит из DataStore, а не из наших рук.

### 8.2. Сохранка забега

```lua
export type SavedRun = {
    challengeId: string,
    seed: number,          -- по нему забег собирается заново тем же кодом
    letters: {string},     -- очередь букв того забега; у математического пуста
    difficulty: number,    -- сложность того забега, а не сегодняшняя
    stage: number?,        -- ступень счёта, если забег был математическим
    level: number?,        -- уровень мира букв: от него зависят буквы на отрезках
    checkpoint: number,    -- индекс пройденной арки, ≥ 1
    savedAt: number,       -- os.time()
}
```

Хранится **рецепт, а не геометрия**. Туннель — сотни частей, их в DataStore
не положишь; сид, буквы и сложность занимают десяток байт, и по ним
`RunCourse.Rebuild` собирает тот же самый туннель — это держится тестом
(`tests/TunnelRun.spec.luau`, «по тому же рецепту собирается тот же туннель»).

Отсюда требование к плану забега: он обязан быть **детерминированным**.
Ничего случайного, кроме `Random.new(seed)`, в нём быть не должно, иначе ребёнок
вернётся в туннель, похожий на свой, но другой, и окажется посреди чужого пути.

Запись появляется, когда ребёнок пробегает арку-сохранку, и исчезает, когда он
пересекает финиш. Выход из игры, тайм-аут и кнопка «домой» её не трогают:
ради этого она и заведена (см. [14-TUNNEL-MODE.md](14-TUNNEL-MODE.md) § 3.3).
Ключ — идентификатор испытания. У мира букв забег один — «Азбучный туннель»
за порталом, — и незаконченный уровень у ребёнка тоже всегда один, поэтому
уровень лежит полем рецепта, а не ключом. Уровень в рецепте нужен по той же
причине, что и ступень счёта: пройди ребёнок следующий уровень на другом
устройстве, эта сохранка всё равно ведёт в свой туннель.

### 8.3. Прогресс по счёту

```lua
math = {
    count_group = { mastery = 3, correct = 12, wrong = 2, ... },  -- TopicProgress
    digit_small = { mastery = 1, ... },
}
```

Ключ — id ступени из `Config/Math`, значение — тот же `TopicProgress`, что у буквы.
Открытость ступени здесь **не хранится**: она считается из статусов
(`Math.isUnlocked`). Две записи об одном и том же рано или поздно разошлись бы,
и ребёнок получил бы открытую ступень с нулевым прогрессом или наоборот.

Одно отступление от правил букв, и оно вынужденное: для статуса «изученная» букве
нужны успехи в двух разных испытаниях, а у математики испытание пока одно —
ворота с числами. Поэтому ей передаётся `minTypes = 1`; требуй мы двух,
вторая ступень счёта не открылась бы никогда. Как появятся «Весы» и сбор предметов
([16-MATH.md](16-MATH.md) § 3.2–3.3), параметр вернётся к двойке.

### 8.4. История занятий

```lua
playLog = {
    { day = 20484, sec = 840 },   -- номер суток по Москве, секунды игры в тот день
    { day = 20486, sec = 1210 },
}
```

Нужна отчёту родителя: «занимался 6 дней из последних 7»
([13-PARENT-MODE.md](13-PARENT-MODE.md) § 2) не выводится ни из серии,
ни из суммарного времени. Ведёт её `Logic/PlayLog`, время приносит `ProfileService`:
перед каждым сохранением — раз в минуту и при выходе — он отдаёт секунды,
прошедшие с прошлого учёта.

- **Сутки — по Москве** (UTC+3). Сервер Roblox живёт по UTC, и без сдвига сеанс
  в 00:30 по Москве попал бы во вчера. Для Владивостока граница уезжает на 7 утра —
  точнее без часового пояса клиента не сделать.
- **День засчитывается от 60 секунд.** Зашёл и вышел — не занимался. Тот же порог
  двигает серию `dailyStreak`, так что серия и счётчик дней не расходятся.
- **Серия в отчёте — на момент отчёта.** Поле хранит серию на день последней игры;
  если с тех пор пропущены сутки, отчёт показывает ноль (`PlayLog.currentStreak`).
- **Хранится 28 дней**, старше — срезается. Отчёту хватает недели.
- Историю чистит `PlayLog.sanitize` на **каждом** входе, а не только в миграции:
  в неё пишут перед каждым сохранением, и битая запись уронила бы сохранение.

До версии 6 серию и время игры не писал никто: поля были, записи не было,
и отчёт показывал нули.

### 8.5. Пройденные уровни

```lua
levels = { letters = 3 }   -- пройдены уровни 1–3, портал ведёт на четвёртый
```

Одно число на мир, а не список: уровни открываются строго по очереди, пропусков
в пути не бывает. Портал играет `Levels.current(levels.letters)` — следующий
за пройденными, а после последнего снова последний.

Уровень засчитывается **по финишу**, сколько бы ворот ни было взято. Статусы букв
для этого не годятся: «изученная» требует успехов в двух разных испытаниях,
и ребёнок, которому нравится только портал, упёрся бы в первый уровень навсегда.
Ступени алфавита (`stages`) при этом живут как жили и открывают буквы падам
площади и Башне по освоению. Путь и освоение — две разные вещи, и хранятся они
отдельно.

Значение проходит `Levels.sanitize` и при чтении, и при записи: чужие ключи,
дроби и числа за пределами уровней срезаются.

## 9. Миграции профиля

```lua
local MIGRATIONS = {
    [1] = function(p)
        -- переход на алфавит: слоги и слова уходят, острова становятся ступенями
    end,
    [2] = function(p)
        -- сохранка забега переезжает в профиль: появляется runs,
        -- мёртвое stages[i].checkpoint уходит
    end,
    [3] = function(p)
        -- у игрока появился участок на спавне: заводим пустой base
    end,
    [4] = function(p)
        -- открылся мир математики: заводим пустой math
    end,
    [5] = function(p)
        -- посуточная история занятий: заводим пустой playLog
    end,
    [6] = function(p)
        -- мир букв стал путём из уровней: заводим levels, туннель без уровня выбрасываем
    end,
    [7] = function(p)
        -- обучение первых минут: кто уже играл, получает его пройденным
    end,
}
```

Правила:
- `version` увеличивается при **любом** изменении структуры;
- миграции применяются последовательно при загрузке;
- поля обычно не удаляются в той же версии, в которой перестали использоваться
  (сначала перестаём писать, через релиз — удаляем).

**Версия 2 — исключение из последнего правила, и оно осознанное.** При переходе
на алфавит `syllables`, `words`, `islands` и настройки эха вырезаны сразу: игра
не опубликована, живых профилей нет, и тащить пустые таблицы в DataStore незачем.

Прогресс по буквам при этом переносится как есть: буква осталась буквой, и всё,
что ребёнок про неё знал, сохраняется. Это проверяется тестом отдельно —
потерять выученные буквы нельзя ни при какой миграции.

**Версия 4** добавляет `base` — участок игрока (§ 8.1). Пустой участок это все нули,
а не отсутствие поля: `nil` уронил бы постройку на первом же входе.

**Версия 5** добавляет `math` — прогресс по ступеням счёта (§ 8.3). Поле отдельное
от `letters`, потому что математика и буквы не блокируют друг друга
([16-MATH.md](16-MATH.md) § 6), а устроено точно так же: у ступени тот же статус,
те же повторения и то же время реакции, что у буквы, и считает их тот же код.

**Версия 6** добавляет `playLog` — посуточную историю занятий (§ 8.4). Прошлое
восстановить не из чего, поэтому история начинается пустой.

**Версия 7** добавляет `levels` — пройденные уровни (§ 8.5). Финиши раньше никуда
не писались, поэтому путь начинается с первого уровня; выученные буквы при этом
остаются. Незаконченный туннель без уровня выбрасывается: по рецепту старого вида
собрался бы уже другой туннель. Потеряна в худшем случае одна сохранка.

**Версия 8** добавляет `tutorial` — сделанные шаги обучения первых минут
([08-UX-UI.md](08-UX-UI.md) § 7). Набор шагов, а не номер текущего: ребёнок
не обязан идти по порядку. Кто уже играл — есть звёздочки, буквы или вещи, —
получает обучение пройденным: вести за руку к паду, где он был сто раз, значит мешать.

**Версия 9** добавляет `parent.restReminder` — напоминание об отдыхе, по умолчанию
включено ([13-PARENT-MODE.md](13-PARENT-MODE.md) § 3). Заодно `parent.dailyLimitMin`
приводится к разрешённым значениям (15 / 20 / 30 / 45 или выключен): мусор в поле
считается выключенным лимитом, а не «ближайшим разрешённым».

**Версия 11** добавляет `levels.math` — путь мира математики (`Config/MathLevels`).
Портал больше не играет «самую высокую открытую ступень», а продолжает путь
по финишу, как в мире букв. Кто играл раньше, получает пройденными столько уровней,
сколько ступеней у него было открыто сверх первой.

**Версия 10** добавляет `daily` — букву дня и её серию (`Logic/DailyLetter`,
[03-CHALLENGES.md](03-CHALLENGES.md) § 7): `{ day, letterId, done, streak, best, lastDay }`.
Серия своя, отдельная от `dailyStreak`: та считает дни игры для отчёта родителя,
эта — пройденные буквы дня и не сгорает при пропуске. Серия начинается с нуля:
переносить `dailyStreak` значило бы заплатить за серию, которой не было.

**Версия 3** убирает `stages[i].checkpoint`. Поле описывало точку на «пути ступени»,
которого в игре так и не завелось, и ни разу не было записано: настоящая сохранка
принадлежит забегу, а не ступени алфавита, и живёт теперь в `runs` (§ 8.2).
